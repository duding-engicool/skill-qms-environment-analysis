## JSON数据格式规范

### 完整数据结构

```json
{
  "org_name": "组织全称",
  "analysis_period": "2024年度",
  "analysis_date": "YYYY-MM-DD",
  "analyst": "分析人员姓名",
  "swot": {
    "strengths": ["列表项"],
    "weaknesses": ["列表项"],
    "opportunities": ["列表项"],
    "threats": ["列表项"]
  },
  "pestel": {
    "political": ["列表项"],
    "economic": ["列表项"],
    "social": ["列表项"],
    "technological": ["列表项"],
    "environmental": ["列表项"],
    "legal": ["列表项"]
  },
  "internal_issues": [
    {
      "dimension": "维度分类",
      "issue": "问题描述",
      "severity": "高/中/低",
      "suggestion": "改进建议"
    }
  ],
  "external_issues": [
    {
      "dimension": "维度分类",
      "issue": "风险描述",
      "likelihood": "高/中/低",
      "impact": "高/中/低",
      "suggestion": "应对措施"
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| org_name | string | 是 | 组织全称 |
| analysis_date | string | 是 | 分析日期，格式YYYY-MM-DD |
| swot | object | 是 | SWOT分析数据 |
| pestel | object | 是 | PESTEL分析数据 |
| internal_issues | array | 否 | 内部问题清单（建议填写） |
| external_issues | array | 否 | 外部风险清单（建议填写） |

## 分析维度详细说明

### SWOT分析维度定义

#### Strengths（优势）- 内部积极因素
- 组织独有的、优于竞争对手的能力
- 可被利用来实现目标的资源
- 评估要点：
  - 质量管理体系运行有效性
  - 核心技术能力与专利
  - 品牌声誉与市场地位
  - 人才队伍专业能力
  - 供应链管理成熟度

#### Weaknesses（劣势）- 内部消极因素
- 阻碍组织实现目标的短板
- 竞争对手可能利用的弱点
- 评估要点：
  - 体系运行的薄弱环节
  - 资源不足或配置不合理
  - 技术能力差距
  - 流程效率低下
  - 组织能力缺陷

#### Opportunities（机遇）- 外部积极因素
- 组织可以开发或利用的条件
- 有助于实现目标的市场变化
- 评估要点：
  - 市场增长趋势
  - 政策法规利好
  - 技术创新带来的机会
  - 合作伙伴拓展
  - 客户需求升级

#### Threats（威胁）- 外部消极因素
- 可能对组织产生不利影响的条件
- 可能阻碍目标实现的挑战
- 评估要点：
  - 市场萎缩或替代品威胁
  - 竞争加剧
  - 法规趋严
  - 技术颠覆风险
  - 经济下行压力

### PESTEL分析维度定义

#### Political（政治）
- 国际贸易政策、关税壁垒
- 政府对行业的补贴或限制
- 地缘政治风险
- 政府采购政策变化

#### Economic（经济）
- 经济增长率（GDP）
- 通货膨胀率
- 原材料和能源成本
- 汇率波动
- 就业率和劳动力成本

#### Social（社会）
- 人口结构变化
- 消费者环保意识
- 健康安全要求
- 生活方式变化
- 教育水平与技能供给

#### Technological（技术）
- 行业技术革新速度
- 数字化转型趋势
- 研发投入与专利
- 自动化与人工智能应用
- 技术标准升级

#### Environmental（环境）
- 碳排放政策
- 资源枯竭风险
- 极端气候事件
- 循环经济要求
- 绿色供应链要求

#### Legal（法律）
- 产品质量法规
- 劳动法变化
- 数据保护法规
- 反垄断与竞争法
- 知识产权保护

## 风险评估矩阵

### 风险等级计算

| 影响程度 | 高 | 中 | 低 |
|---------|-----|-----|-----|
| **高可能性** | 重大风险 | 高风险 | 中风险 |
| **中可能性** | 高风险 | 中风险 | 低风险 |
| **低可能性** | 中风险 | 低风险 | 可接受 |

### 风险响应策略

| 风险等级 | 响应策略 | 处理时限 |
|----------|---------|---------|
| 重大风险 | 立即制定应对计划，管理层介入 | 1个月内 |
| 高风险 | 制定应对计划，明确责任人 | 3个月内 |
| 中风险 | 纳入监控清单，定期评审 | 半年内 |
| 低风险 | 保持关注，记录在案 | 年度评审 |

### 问题严重性评估

| 等级 | 定义 | 对QMS影响 |
|------|------|----------|
| 高 | 体系运行严重受阻或不合规 | 可能导致认证暂停/撤销 |
| 中 | 部分流程受影响 | 影响部分绩效指标 |
| 低 | 局部改进机会 | 优化空间但不影响基本运行 |

## 格式验证规则

1. **JSON语法**：所有数据必须符合JSON格式规范
2. **非空校验**：
   - `org_name`、`analysis_date`必填
   - `swot`每个维度至少1条
   - `pestel`每个维度至少1条
3. **枚举值校验**：
   - `severity`仅允许：高/中/低
   - `likelihood`仅允许：高/中/低
   - `impact`仅允许：高/中/低
4. **字符限制**：
   - 每条分析内容建议不超过100字
   - 建议每维度3-5条为佳
